2. Entorno

  • Windows 11, JDK 21 (Temurin), Maven 3.10, Spring Boot 4.1 con Hibernate 7.4.
  • Base de datos H2 en memoria con el perfil demo y sus datos de ejemplo.
  • Navegador: Chromium con Playwright, en 1280 × 800 y en 375 × 812 (celular).
  • Aplicación móvil: Node 22, Vitest, Playwright y la simulación de la API de Postman.
  • Base de datos real: una instancia temporal de la MariaDB 10.4 de XAMPP, para la colección de Postman y el recorrido de las funciones nuevas.
  • Publicación: Render, plan gratuito (API en Docker y página como sitio estático), y Vercel (aplicación móvil).

8. Errores encontrados y corregidos

ErrorCausaCorrección
El segundo usuario sin correo o sin celular no se podía guardar.Se guardaba texto vacío en columnas únicas.Se guarda NULL. Prueba dosUsuariosSinEmailNiTelefonoNoChocan.
Listar facturas fallaba al convertir a JSON.Relaciones perezosas de Hibernate.@JsonIgnore en las relaciones.
«Datos de la tienda» respondía 500 al listar.Relación perezosa con el administrador.@JsonIgnore; el texto además acepta números.
El CI de main fallaba en dos pruebas de ingresos.Faltaba simular un tipo de factura y una comprobación esperaba el total en lugar de lo de papelería.Pruebas corregidas; ahora comprueban cada tipo.
Con la base de XAMPP (MariaDB) no se podía registrar ninguna venta (error 500).El conector la presenta como MySQL y se generaba una consulta de bloqueo que MariaDB no entiende.El modo local usa el dialecto de MariaDB.
En el celular, el panel y «Lo vendido» quedaban más anchos que la pantalla.Los botones de las tarjetas no pasaban a otra línea.Los botones se acomodan en varias líneas. Caso P-33.
Los ingresos de las ventas de la caja salían en cero.Las ventas mezclan tipos en una factura («Venta en tienda»).Se suman por línea. Prueba lasVentasDeLaCajaEntranEnElResumenDeIngresos.

9. Cómo repetir las pruebas

cd backend
mvn test                                              (pruebas del backend)
mvn spring-boot:run -Dspring-boot.run.profiles=demo   (para Postman y las pantallas)
cd movil
npm test                                              (pruebas unitarias)
npm run test:e2e                                      (recorridos en el navegador)
jwebserver -d frontend -p 5500
node 07-entrega-final/fuentes/probar-pantallas.mjs    (con el backend recién encendido)

En Postman: importar postman/papeleria-matrix.postman_collection.json y el entorno Local o Render, y ejecutar la colección completa. Las carpetas 5, 6 y 7 usan los usuarios de prueba del modo demo.
